First prompt:
is the string terminator, '\0', read as one character, similar to a newline?

Response:
Yes. '\0' is a single character value, just like '\n'.
The difference is what that character means:
'\n'   // newline character
'\0'   // null character, numeric value 0

In a C string:
char word[] = "cat";

memory actually contains:
'c'  'a'  't'  '\0'

So "cat" uses 4 bytes in a char array, even though strlen("cat") is 3 because strlen stops when it reaches '\0'.
One useful distinction: '\0' is a character with value zero, while " \0 "-style double quotes would make it part of a string literal.

Second prompt:
printf("Address at index 0: %p \n", (void *) prices[0]);
Would this work, or do I need an ampersand?

You need the ampersand.

printf("Address at index 0: %p\n", (void *)&prices[0]);

Your version:

(void *) prices[0]

takes the integer value stored at index 0 and treats that integer as though it were an address. That is not what you want.

These are the key differences:

prices[0]    // value at index 0
&prices[0]   // address of index 0
prices       // also points to index 0

So this is equivalent and a little cleaner:

printf("Address at index 0: %p\n", (void *)prices);

And %p expects a void *, which is why the cast to (void *) is appropriate.

Third prompt:
I am working in a directory in my local repo. The repo already has a gitignore, do I need a  gitignore in this directory,   too?

Response:
Usually, no.
A .gitignore in the repo root applies to files and folders inside subdirectories too.
So if your repo looks like:
repo/
├── .gitignore
├── hw14/
│   ├── menu.c
│   ├── main.c
│   └── menu

and the root .gitignore contains:
menu
*.o

those ignore rules can apply inside hw14/ as well.
You’d only need another .gitignore inside the subdirectory if you want rules that are specific to that folder or you want to organize ignore rules locally.
One thing to remember: .gitignore only affects untracked files. If a file was already committed, adding it to .gitignore later won’t make Git stop tracking it.
