Part A questions:

In the worst case, why must find_code look at every cell?
    Because if there was a "Blank" picture, and we were looking for a "1", it would never show up. Similarly, a 1 in the bottom-right corner would
    cause the function to search the whole array up to the last index.
Why is COLS part of the parameter type pic[][COLS], while the number of rows is a separate argument?
    COLS must be part of the parameter since C needs to know how wide each row is.
What does the array store, and where does the printed glyph (such as # or █) come from?
    The array stores ones and zeros. The printed glyph comes from my logic, which prints out the glyph correlating to the code.

Part B questions:

If set_cell is given row == nrows, why must it refuse the write?
    Because pic[row][COLS] would be out of bounds. Lets say you have 3 rows. Since they are zero-indexed, index 3 would be the fourth, which is outside of the array.
Row-major order means the scan finishes a row before it starts the next. What is the flat index of pic[2][3] when COLS is 5?
    13.
