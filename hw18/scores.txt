Part A answers:

Valid indices for an array of length n run from which value to which value? What does C do if you read scores[n]?
    Valid indices run from zero to n-1. If you try to read scores[n], the behavior is undefined in C.
Why does sizeof(scores) / sizeof(scores[0]) work in main on the actual array, but fail inside a function that took const int scores[]?
    Because in a function, this is treated like a pointer instead of the actual array. In main, it works since it takes the size of the actual array.
For int board[3][4], which element is board[1][2] (row, column, and a one-sentence note on row-major layout)?
    This is the second row, third column. This board has 3 rows and 4 columns.

Part B answers:

Why must a function that receives an array also receive the length?
    Because sizeof(scores) / sizeof(scores[0]) does not work inside the function. The size being passed in is useful when making for loops to traverse the array.
In your 2D print loop, which index is the row and which is the column? What goes wrong if you swap them?
    In my print loop, the first index is the row and the second is the column. If they are swapped, The program could crash out of bounds, since I have more columns than rows.
